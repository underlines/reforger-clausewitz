# Changelog

All notable changes to Clausewitz. Format: [Keep a Changelog](https://keepachangelog.com/), versioning: [SemVer](https://semver.org/) (from 1.0: MAJOR = breaking for saved configs/scenarios or the sidecar protocol, MINOR = features, PATCH = fixes).
Add a line under `[Unreleased]` with every user-visible change; `_tools/release.ps1` rolls it into a version.

## [Unreleased]

## [1.2.0] - 2026-10-14

### Added
- Configurable LLM sidecar endpoint: command line `-clwSidecar <url>` or `sidecarUrl` in `$profile:Clausewitz/overrides.json` (default `http://127.0.0.1:8788/`), token via `-clwSidecarToken <token>` or `sidecarToken`; the server log shows the URL in use (`CLW: sidecar url ...`). Sidecar: `CLW_ALLOWED_HOSTS` for a sidecar on another machine behind a domain or public IP.
- Languages: mod texts in English and German (string table); every player gets SITREPs, HQ replies and mission texts in their game language, or the one chosen with `/hq language <code>` or in the HQ menu; broadcast SITREPs are translated per language by the LLM.
- Sidecar: separate strong and weak LLM slots (decisions vs. translation), an optional backup model per slot, dashboard in English and German.
- Friendly units on the in-game map: own position, squadmates, own squads and vehicles (setup switches `mapMe`, `mapSquadmates`, `mapSquads`, `mapVehicles`).
- HQ chat: per-player conversation history; new player requests "mission" and "status" (`REQUEST_MISSION`, `REQUEST_STATUS`).
- Loadouts (beta): save your kit at any arsenal (vanilla, RHS, WCS), restored as "My saved loadout" in the spawn menu after restarts; server loadout library edited on the sidecar dashboard (Loadouts tab) and synced at war start; squad roles with unique role kits.
- Sidecar dashboard admin login (default password in the README, change it on first login) and an optional game token (`gameToken`) for the game endpoints.

### Changed
- Spawned infantry of pack factions belongs to the buying faction, so pack squads (e.g. TF_US / TF_RF) can be joined.
- Players without a character are parked during setup until the war starts.

### Fixed
- Collision-free vehicle spawn spots (road first within 50 m, size-aware, keeps clear of base services).
- The game now sends the sidecar token on situation and manifest requests too (before only on loadout requests).

## [1.1.0] - 2026-10-13

### Added
- Readable squad names everywhere (`1st Rifle Squad`, `Recon Team 1`, `Motorized Squad 1`, `Mechanized Squad 1`, `Armor 1`, `Supply Truck 1`, `FOB Team 1`, `HQ Garrison`): group list, HQ menu, map markers, situation (`name` per squad; orders keep the `id`). Dismount groups of motorized/mech squads and recon teams are joinable again under their parent's name.
- HUD: own side's supplies centred in the ticket row.
- Vehicle depot: one "Request vehicle" action opens a paged vehicle list (category filter: light, motorized, mech, armor, logistics) with the whole side pool incl. pack vehicles (M1 Abrams, M2 Bradley, JLTV); the vehicle spawns at that depot and is paid from that base's stock.
- In-game map: FOB base marker with its state (`FOB1 (planned)` -> `(building N %)` -> `FOB1`) and following task markers `<unit> -> <destination>` for FOB builders, escorts and convoy trucks; dashboard FOB base icon, status label and arrows builder -> site and truck -> destination; squad names on the dashboard.
- Rematch in place: after the war ends the results stay `rematchDelaySec` (60 s), then the same session returns to setup without a world reload (no more `JIP_ERROR` kick); leftover AI and vehicles of the finished war are swept. overrides.json `rematch`: `inPlace` | `reload` | `off`.
- HQ war journal (LLM): per faction intent, 3 goals, 3 lessons (review call every `memory.reviewMin` minutes) and code-counted attack tries/fails, injected into the commander and `/hq` prompts with "do not repeat an attack that failed twice"; dashboard Journal tab and memory toggle. Game reports attack outcomes; objectives carry `side` (left/centre/right) for a flank nudge.
- Economy guard: mode params `hqReserve` (100) and `convoyMinLoad` (60): AI purchases, the LLM buy action, AI FOB spending and convoys never take the HQ stock below the reserve (player requests still may); no AI buy attempts at the AI cap; idle stand-down check log.
- overrides.json `sides` / `sidesDefault`: `kinFill` (`missing` | `all`: kin vehicles also for roles the side already has), `kinWeight`, `kinAllInfantry`.
- Urban HQ sites for random/auto starts: scored search near vehicle roads and villages with room for the base; small replicated obstacles (vegetation, fences, clutter) in a service footprint can be cleared (`Configs/CLW/Placement/ClearRules.conf`); the depot faces the road.
- Logs: kit purchases (`CLW: kit <player> ... (stock a -> b)`), depot/arsenal supply check 10 s after spawn, depot list size per side.

### Changed
- Base 30 % tighter: the command post sits on the HQ point, the spawn point right beside it (radius 4 m), arsenal and supply cache around the command post; the vehicle depot about half the old distance, next to a road where one is near.
- Only the command post gets a request terminal (none at the depot).
- Time limit can be set from 5 min.
- The engine game end (`EndGameMode`) is no longer called after a war by default.

### Removed
- Field hospital (medical service) from base services, the FOB upgrade (tier 2 = vehicle depot only), faction profiles and prop sets.

### Fixed
- Supplies drained to ~40 and convoys emptying the HQ to 0.
- Client map-marker restore ran on every faction flip in the deploy menu; now once per real change.

## [1.0.0] - 2026-10-12

### Added
- M4 any map: scenario per world (the scenario attribute only for the worlds its `m_aWorlds` lists, then `Configs/CLW/Scenarios/<world>.conf`, then a scenario listing the world, else the **auto scenario**). The auto scenario (`_Auto.conf`, `CLW_AutoScenario`) fills a map at game start: HQ pair from the random-layout search (strict, then relaxed), objectives from named map places in the band between the HQs (towns first, line points otherwise), counts per battle size, FOB sites computed. Log `CLW: scenario ... (source attribute|by-world|by-listing|auto)`, `CLW: auto ...`.
- Wrapper worlds `Worlds/CLW_Eden.ent` (Everon) and `Worlds/CLW_Cain.ent` (Kolguyev) on the campaign navmeshes; `dev/tools/new-map-wrapper.mjs` generates the wrapper compat addon for any map mod (`dev/notes/maps.md`).
- Side pools: a side's buy catalog takes the roles it lacks (supply truck, missing kinds) from kin factions (friendly list, profile `m_aKinFactions`, overrides.json `sides.kin`), never the enemy side, so pack factions (RHS) get supply trucks and convoys. Vehicles without a default crew are detected at catalog build (spawn probe) and kept out of the AI buy mix (player vehicle requests still offer them).
- overrides.json `sides` (`ownOnly`, `kin`, `excludeFactions`, `excludePathContains`) and `props` (per role a prefab, `vanilla` or a style set); prop style sets `Configs/CLW/Props/PropSets.conf`; the prop resolver runs admin override > style sets > faction data > vanilla set and validates every prefab.
- HQ menu: "Open HQ menu" on the request terminals and `/hqmenu`: Requests (five kinds with type choice, cost and refusal reason), Squad (join/leave HQ squads, SITREP), Base (stock, FOBs, convoys) and Contact report, running the same server code as `/request` and `/report`. A granted vehicle request says "vehicle delivered, grid ..." and puts a temporary own-side map marker at the vehicle.
- FOB builders escalate on a stall (build where the builder stands when close, relocate onto valid ground near it, take a nearer site, swap the builder, route via a road point); walking builders use a forced move and pick a closer site when they start far away.
- Random start positions: setup parameter "Start positions" (`startPositions`: `fixed` = today's scenario HQs, default | `random`) and "Random seed" (`randomSeed`, 0 = new each war; the seed used is logged). `CLW_RandomLayout` picks a random axis and centre inside the terrain (margin from the edge, no sea between the HQs), puts the HQs at the battle-size distance (down to 15 % less, never above), and validates each with `CLW_FreeSpot` (clear core, flat, dry, free ring for the base services, road near, not in a dense town), retrying up to 30 times before falling back to `fixed` with a WARNING. Objectives are carried over from the scenario pattern (rotated and scaled onto the new HQ line), snapped to a nearby town/village from the map descriptors, else kept if the spot is clear, else nudged; FOB sites follow the HQ line as before. All limits are scenario data (`m_RandomLayout`, `CLW_RandomLayoutSetup`, Arland ships the defaults). It reuses the battle-size layout path, so bases, spawn points, markers, services and FOB sites see the new positions. Log lines `CLW: layout random seed=... axis=... centre=... hqA=... hqB=... (attempts N)` and `CLW: layout objective <id> -> <pos> grid (snapped to <name>|kept|nudged)`.
- Game Master takeover (opt-in): with `-clwTakeover` on the server command line (or `"takeover": true` in overrides.json) Clausewitz runs its war inside a foreign game mode, e.g. a vanilla Game Master world (`-server worlds/GameMaster/GM_Eden.ent`), without a wrapper world. The war logic moved from the `CLW_GameMode` entity into `CLW_WarRuntime`, hooked from a modded `SCR_BaseGameMode`. Scenario: `-clwScenario <name>`, else the world name without `GM_` (`GM_Arland` -> Arland), else the normal chain. Default off: a GM server that merely loads Clausewitz stays vanilla. Log `CLW: takeover step <n> ... ok|FAILED`.
- Start ownership (`CLW_ScenarioConfig.m_sStartOwnership` authored|nearest|none, `m_iStartOwnedPerSide`) and setup parameter "Start objectives" (`startObjectives`: scenario|none|1|2|3). Owners are resolved at war start AFTER the battle-size layout: "nearest" gives each side the kept objectives closest to its own HQ (relative distance), at least one stays neutral. The auto scenario uses "nearest"; an authored scenario with random start positions switches to "nearest" with its authored count. Log `CLW: points start owner ...`.
- RHS prop style sets: RHS_USAF, RHS_AFRF and RHS_ION get their own RHS arsenal boxes (base arsenal and FOB kit); other roles fall back as before (RHS ships no own compositions). Research `dev/research/rhs-prop-sets.md`.
- Map wrapper generator: checks that every `{GUID}` reference of the generated files is registered (map, Clausewitz, base game) and prints a ready-to-paste block for the local dedicated server (junctions, packs file, start line). First generated wrapper (Takistan) verified on the dedicated server.
- Server setup preset (`setup` in `$profile:Clausewitz/overrides.json`): mode, factions and mode parameters for an unattended war start on a dedicated server (`autoStartSec`, `-1` = only pre-fill the menu); the values are also the setup menu defaults; an invalid preset keeps the war in setup with `CLW: ERROR setup preset ...`.
- FOB timing gate: a side may establish a FOB only after `fobEarliestMin` minutes (default 6, 0 = off) and once it knows the front (an enemy contact, a contested objective or an objective that changed hands); the refusal ("too early for a FOB: ...") is the same for the LLM, the rule commander and the HQ menu. Sites are ranked by closeness to the front objective. Sidecar prompt, validator and fake provider follow (`fobRules.ready`).
- HQ garrison and idle stand-down: `garrisonSquads` (default 1) infantry squads per side defend the HQ and are never sent away; a squad idling at the base without orders for `idleDespawnMin` minutes (default 6, 0 = off) is stood down and its cost refunded. Purchases carry their order (the rule commander buys only for unmet tasks, LLM `buy` entries need `command` + `target`/`pos`), applied when the unit is ready.

### Fixed
- Auto scenario start owners were picked among the central objectives only, so with a bigger battle an owned objective could lie further from its HQ than a neutral one (Everon: C owned by US while B was further out).
- Generated map wrappers left the AI without a navmesh: their own AIWorld prefab was not registered (a generated addon has no resource database: `Wrong GUID/name ... CLW_AIWorld_<World>.et`). The wrapper now places the map's AIWorld prefab directly (or vanilla `SCR_AIWorld` with the navmesh components inline).
- Pack arsenal boxes that ship a zero buy multiplier (RHS) gave kits away for free although kit cost was on; the multiplier is set to 1 at base setup.
- Random start positions failed on Arland (60 of 60 attempts rejected, mostly water): HQ wishes are sampled from dry land only (near map places and roads), 120 attempts, a rejection histogram per search.
- Map place positions were (0,0) on a dedicated server (map items are not positioned headless): they now come from the item's owner entity, so place names in reports, random-layout wishes and the dashboard locations are right.
- Re-issued FOB builder and convoy truck move orders were silently ignored (same target); loaded convoys that failed lost their cargo silently; a FOB relocation could leave it building without a builder; a kin faction's truck counted as captured; a freshly bought truck could end its convoy before loading.
- AI purchases of vehicles without a default crew (RHS K-17, K-4386 variants) no longer fail and refund.
- Duplicated spawn points in the deploy menu / map: the scene-placed spawn points (`SpawnPoint_US` / `_USSR`, named "US Point") were only disabled, never removed, and a disabled point still shows next to ours (and after a side re-key they kept the old faction key and were not even touched). `CLW_Bases.PruneForeignSpawns` now deletes every plain spawn point that is not the base or FOB point (at start, 4 s later, after a re-key and after a FOB is built); log `CLW: bases spawn points deleted=N (foreign), now per side: ...`.
- Spawn points now have a readable name that replicates to clients: the base point uses the scenario base label ("US HQ"), a FOB point "FOB1 <site name>"; the HQ point is the default pick in the deploy menu.
- Arsenal pool items (kin pool / pack rules) could not be taken and showed no price: the catalog entry lookup now uses the pool.
- GM takeover: supplies are switched on (Game Master modes disable them, so arsenals had no prices and kits were free).
- Clients lost the own-side map markers created during the setup-to-war faction switch (vanilla drops markers of a foreign faction for good); they are now kept and restored when the client's faction changes.

### Changed
- A new FOB is no longer just an invisible spawn point: a compact kit stands at the spawn point (small arsenal box, supply box linked to the FOB stock like the base supply, five sandbag segments in an arc), placed on clear ground within 14 m of the site and removed with the FOB. Data: `m_aFobKit` in the faction profiles (US, USSR, FIA ship one; sides without a kit use the kin faction's, else the old tier-1 services). Arsenal and supply box get map markers; the extra "FOB1" location marker is only used when no kit piece exists. Tier 2 (`UPGRADE_FOB`) is unchanged. A kit FOB has no command post, so it is no longer lost by destroying one (enemy presence still loses it).
- New `CLW_PropResolver`: one choke point that resolves a role ("service.arsenal", "fob.supply_box", "fort.sandbag_long", ...) of a side to a prefab (own profile, named fallback faction, kin faction); the base services and the FOB kit both use it. Log `CLW: props <side> <role> -> <prefab> (source ...)`.
- Base services stand compactly around the HQ (rings start at footprint + 5 m, 3 m gaps; an authored offset is tried first). The vehicle depot is affiliated with its side, lists that side's vehicle catalog (kin faction fallback) and pays from the base supply stock.

## [0.5.0] - 2026-10-12

### Added
- M3 phase B, base services: every side gets its service compositions at its HQ at war start (command post, supply cache, arsenal, vehicle depot, medical), positioned on free spots around the base and listed per base for later requests/FOBs. Prefabs come from the faction profile data (`m_aServices`, US, USSR and FIA ship them); a faction without services uses its kin faction (`m_sServiceFallbackFaction` or a friendly faction with services), so RHS/WCS/GRS sides get a base too. Log lines `CLW: services ...`.
- Supply link: the base supply containers mirror the side supplies; arsenal kits spend the same supplies as purchases (changes in both directions are synced every 1.5 s).
- Arsenal kin pool: during a Clausewitz war each faction's arsenal also lists the items of factions friendly to it (pack factions list the vanilla faction they are built on), never the enemy side; saved kits accept friendly items.
- Arsenal pack rules (`Configs/CLW/ArsenalPackRules.conf`, `CLW_ArsenalPackRules`): data rules "items of faction catalog X (optionally only prefab paths containing Y) also go to faction Z", plus a list of prefab path texts blocked from every arsenal, applied on top of the kin pool with the same enemy-side exclusion. Research on how WCS and GRS reach the factions: `dev/research/arsenal-packs.md`.
- Setup menu: "Logistics" and "Kit cost" switches (kit cost off = arsenal kits are free).
- M3 phase R, action registry: one registry (`CLW_ActionRegistry`, data in `Configs/CLW/Actions/Actions.conf`, executors as script classes) behind every HQ command. The LLM orders (MOVE/ATTACK/DEFEND/RECON/FALL_BACK), purchases and mission offers are validated and executed through it (no behaviour change). War modes declare capabilities (`CLW_Capabilities.Has`, switchable with `cap_<name>` mode params); registry entries whose capabilities are off drop out. Protocol v3: the game sends its action manifest to the sidecar (`POST /manifest`, hash in every situation), the sidecar builds the prompt command list, the validator and the fake provider from it and falls back to a built-in manifest (v2 posts keep working); the dashboard shows the manifest in the HQ view data (`/api/state` `manifests`).
- M3 phase Q, player requests and reports (no LLM needed): chat `/request vehicle|squad|resupply|reinforce|recon [arg]` (`/request` alone lists the options with costs) and a request terminal prop beside each side's command post and vehicle depot (actions "Request squad / vehicle / resupply" with the cost in the label). Requests run through the action registry (`REQUEST_*`, authority player, capability `requests`): squad leaders may ask for an AI team that joins their squad, a reinforcement or a recon group; soldiers for resupply and a vehicle; supplies, AI/vehicle caps, engine AI headroom and a per-player cooldown decide, the answer comes as hint plus chat line (granted, or refused with the reason). `/report <count> <inf|veh|armor> <dist> <dir>` and enemy military symbols that players place on the map become contacts (source human, confidence from config, expiring like AI contacts; capability `reports`). The situation carries `requests[]`, the dashboard has a Requests tab. Log lines `CLW: request ...` / `CLW: report ...`.
- M3 phase F, FOBs: a side can establish forward operating bases (`ESTABLISH_FOB <site>`, `UPGRADE_FOB <fob>` on the action registry, so the LLM and the rule commander use the same path). The cost is paid up front (refunded if the FOB fails), a transport (free motorized unit, else bought through the force spawner) with an escort drives to the site and builds it (`CLW_BuildExecutor`: `instant` on arrival, or `timed` over the build time while the builder is on site; progress logged every 25 %). A standing FOB has a respawn point (respawn at ticket cost like the base), command post, supply cache and arsenal; the upgrade adds vehicle depot and medical. An enemy alone in the zone for 45 s or a destroyed command post loses the FOB (spawn point and services removed, tickets lost, announcement). Without the logistics switch the FOB is built abstractly (no truck). Sites come from scenario data (`m_aFobSites`, absolute or relative to the HQ line, Arland has four) plus computed ones, validated for ground, road, distance to bases/objectives/FOBs and enemy contacts. Setup menu: max FOBs, build mode, cost, build time. Situation: `fobs[]`, `fobSites[]`, `fobRules`; sidecar: FOB prompt paragraph, `fobs` reply channel, validator, fake provider; dashboard: FOB markers on the map. Log lines `CLW: fob ...`.
- M3 phase A, HQ chat: `/hq <free text>` talks to HQ over the radio. With the LLM sidecar online, an agent turn (Vercel AI SDK `ToolLoopAgent`, max 4 steps, OpenRouter) reads the message, may look at own forces, bases and known contacts (fog-limited), and queues the matching player request (`REQUEST_*` registry entries; entries beyond the first six are found with a tool search); the game runs each queued action through the action registry as the requesting player, so the `/request` grant rules (role, cooldown, supplies, caps) apply, and answers with the radio reply (short, in the player's language) plus the result. Without the LLM, or after 60 s without an answer, the player gets the `/request` menu hint. The situation carries `hq[]` (pending messages), the reply `hqActions[]` / `hqReplies[]`. Sidecar: new `dev/tools/package.json` (`ai`, `@openrouter/ai-sdk-provider`, `zod`; run `npm install` in `dev/tools` once; the strategic tick still needs no dependency), `agent/agentTurn.mjs`, fake provider with keyword mapping, `agent` settings group, `CLW_CONFIG` env for a second instance, dashboard "HQ chat" tab (steps, tool calls, actions, reply, cost, latency). Log lines `CLW: hq ...`.
- M3 phase L, logistics: with the `logistics` capability (on by default, setup switch "Logistics") each FOB has its own supply stock; income and all HQ purchases keep using the side ledger (= HQ stock). New intents `RESUPPLY <fob>` (HQ -> FOB) and `CONVOY <origin> <dest>`: a supply truck (new catalog kind `logistics` with a cargo amount, data in the faction profiles) loads min(capacity, source stock) at departure, drives there and adds the cargo to the destination stock; a destroyed or captured truck loses the cargo (event for the LLM). Max convoys in flight per side: setup parameter "Max convoys per side" (`convoyMax`, default 2). The rule commander resupplies a FOB whose stock runs low; the situation carries `stock` (bases[], fobs[]), `convoys[]` and `logisticsRules`; sidecar prompt paragraph, fake provider and dashboard (stock numbers, convoy markers) follow. FOB upgrades, kits at the FOB arsenal and requests made at a FOB terminal draw from that FOB's stock. Logistics off: one pool as before, FOBs fed abstractly.
- Base structure markers: placed services (HQ and FOB) get a map marker with a readable label ("Arsenal", "HQ command post", "FOB1 arsenal"), visible only to its own side (see the reduced marker set below); removed with a lost FOB and at war end. The situation carries `structures[]` (base, kind, label, pos, grid) per side; the dashboard map has a "structures" layer (lettered squares, hover info); the sidecar keeps it out of the LLM prompt. Log lines `CLW: markers ...`.
- Own-side map markers reduced to the essentials: only the HQ and FOB locations plus the important structures (command post, arsenal, vehicle depot / requests, supply cache) get a marker, visible only to their own side; field hospital and repair bay have none (`CLW_ServiceEntry.m_iMapMarker`: -1 by kind, 0 off, 1 on). The HQ base marker of the control points is now own-side only (it was visible to everyone), and an active FOB gets a "FOB1" location marker for its side that is removed when the FOB is lost. Enemy bases and FOBs are not shown. The dashboard `structures` block still lists every service. Log lines `CLW: markers ...` / `CLW: points base marker ...`.
- Sidecar dashboard reachable in the LAN with `CLW_HOST=0.0.0.0` (host/origin checks then accept private-network addresses; the API key is never sent to the browser).

### Changed
- Debug lines (spawns, orders, missions, contacts, point captures, ...) no longer appear in players' chat by default; they stay in the log and are sent to the sidecar, whose dashboard has a new "Debug log" tab. Set `"debugChat": true` in `$profile:Clausewitz/overrides.json` to show them in chat again. War-over and hold-all announcements stay visible.
- `/request vehicle` (chat): a requester within 300 m of a vehicle depot (HQ or an active FOB) gets the vehicle at that depot as before; further away it is placed near the requester: on the nearest road within 50 m (on the road edge, aligned with the road, else the shoulder), otherwise on open flat ground within 30 m, always collision-free. Requests made at a request terminal keep using the depot of that terminal's base. The answer says where ("at the roadside near you"). `/request squad` forms its team on clear ground beside the vehicle depot (nearest to the requester, or the terminal's) instead of in the HQ spawn zone.
- SITREP hint (H) shows about twice as much text (mission 320, enemy 240, situation 220 characters, 800 total).
- `/hq`: the radio reply and the result of the action it triggered arrive together in one HQ hint (15 s) plus a chat line.

### Fixed
- Compositions, request terminals, resupply boxes, squad clusters and FOB clusters keep off roads (owner test 2026-10-12: the arsenal stood in the HQ road and blocked AI trucks): the free-spot search rejects any pose whose rotated footprint comes closer than 4 m (`CLW_SpotParams.m_fRoadClearance`) to a road edge (centreline minus half the road width; footpaths under 2 m width ignored), reason `road` in the `rejected:` log summary, `roadSegs=` shows the cached segments (one road query per search). All three service passes keep the rule; vehicles (roadside parking) are exempt. The last-resort FORCED ring in `CLW_Services.FindSpot` is replaced by a best-effort search that ignores only the slope (road and object clearance kept, `slope-ignored`); FORCED is logged only if that fails too.
- Arsenal pool log (`CLW: services arsenal pool <faction>`) showed `own=0` for every faction because it ran before the catalogs were filled; it now counts the whole catalog once the faction has items and lists own / kin / rule / blocked counts.
- FOBs: a builder that makes no progress toward the site for 120 s (fighting near an objective) no longer keeps the FOB in MOVING forever: within 300 m of the site the FOB is relocated to valid ground near the builder and built there, otherwise the move is re-issued and the FOB is cancelled (refunded) after 3 stalls. FOB sites (scenario data and computed) keep at least 250 m from every objective (capture radius edge); a data site that is closer is shifted away from the objective or dropped, with a log line (`CLW: fob site ...`).
- Request terminals only serve requesters of their own side (the side is bound when the terminal spawns, the server checks it), and the request terminals of a lost FOB are removed with it.
- Purchases are refused up front (before supplies are spent) when the engine active-AI limit has no room for the unit (headroom = limit - active - margin 6 - AI of purchases in progress); the situation carries `war.engineAI {active, limit, headroom}`, the rule commander and the fake LLM provider skip buys without headroom, the LLM prompt says so, and starting a war logs a warning when both AI caps together exceed the limit.
- HQ purchases no longer fail with "no members arrived" once about 90 AI are alive: purchased groups are spawned with CRITICAL importance (the engine admits NORMAL groups only below 70 % of the active-AI limit and silently drops the request otherwise), an empty group re-requests its members twice before the purchase is refunded, and spawn logs show the active AI count. New groups are also exempt from the activity budget for 60 s.
- Collision-aware placement (`CLW_FreeSpot`): base services (command post / HQ tent, field hospital, supply cache, vehicle depot, arsenal box), request terminals, resupply boxes, FOB sites, FOB respawn points and requested vehicles are no longer put inside fences, walls, buildings, trees or props. A candidate pose is accepted only when its whole footprint is dry, flat enough (3x3 terrain samples, height range limit), clear of every solid world object (entity query over the rotated footprint box plus cylinder traces; decals, road meshes, grass and bushes do not block; trees and vehicles do) and clear of the other placed services. The footprint of a composition is derived from the child objects of its prefab (no test spawn) or set per service with the new `m_vFootprint` (half X, height, half Z) in the faction profile. Every decision logs `CLW: place <label> at <pos> grid <grid> yaw ... tries ... rejected: <reason counts>`; a service that finds no clear ground retries wider with trees ignored and only then falls back to a forced spot (`CLW: place ... FORCED`, warning). Service log lines now carry the map grid.
- FOB sites are validated for room: a data or computed site shifts (up to 35 m) to clear ground for the command post cluster or is rejected; builder relocation uses the same check.
- Chat commands (`/request`, `/report`, `/hq`, `/sitrep`, `/war`) never reached the server on a dedicated server: the world had no chat entity ("missing ChatEntity"); `CLW_Arland` now places the vanilla `ScriptedChatEntity`.
- War start on other factions than the setup sides (e.g. RHS instead of US/USSR): players already in the game switch faction through the vanilla client request and every client gets the new playable sides, so the deploy menu shows the right teams and loadouts without a rejoin.
- The HQ composition's own spawn point is deleted instead of disabled (a disabled point showed and was preselected in the deploy menu: players could not spawn).
- Dashboard map on a dedicated server: the map extent comes from the terrain (the server reports map size 0, the overlay drifted ~10 % against the map image).
- Service placement on hilly ground: the slope limit is a grade relative to the footprint (8 / 14 / 25 % per pass) instead of a fixed height range; FOB sites search up to 80 m for clear ground.

## [0.4.0] - 2026-10-12

### Added
- Faction SITREP for players: one briefing per side (BLUF headline, Situation, Intel, Mission, Execution, Logistics) in natural NATO/US military prose (sizes and times in words, objective or nearest map place plus a 100 m grid matching the map labels, no unit ids or coordinates). Built in game every 20 s from that side's own picture (works without the sidecar); the LLM version rides in the commander reply (no extra call) and replaces it while fresh.
