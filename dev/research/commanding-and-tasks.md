# Vanilla AI commanding + SCR_Task: how it works, preconditions

Labels: [SRC] = verified in base-game source (scripts/Game/..., Prefabs/... via game_read); [WIKI] = BI wiki. No forum claims were needed.
Wiki: https://community.bistudio.com/wiki/Arma_Reforger:Commanding_Menu_Modding , https://community.bistudio.com/wiki/Arma_Reforger:Task_System_Usage

## 1. Commanding end to end
- Data model [SRC]: a player-led "master" SCR_AIGroup (playable group, holds the players) owns an AI "slave" SCR_AIGroup (prefab `Prefabs/AI/Groups/Slave_Group.et`, CommandingManager attr `m_sAIGroupPrefab`). ALL commands target the SLAVE group (`playersGroup.GetSlave()`).
- Slave creation: `SCR_GroupsManagerComponent.CreateNewPlayableGroup` spawns it when a CommandingManager exists (then `RequestSetGroupSlave`), else lazily by client `RequestCreateSlaveGroup` -> server `RPC_AskCreateSlaveGroup` (requires `group.IsPlayerLeader(playerId)` and no slave yet). Scene-placed groups never go through CreateNewPlayableGroup.
- SCR_CommandingManagerComponent (SCR_BaseGameModeComponent on game mode prefab) [SRC]: attrs `m_sAIGroupPrefab`, `m_sCommandsConfigPath` (default Configs/Commanding/Commands.conf), `m_iMaxAIPerGroup` (Conflict sets 4). Loads SCR_PlayerCommandsConfig -> list of SCR_BaseRadialCommand; the list INDEX is what goes over the wire. Singleton `GetInstance()`.
- SCR_PlayerControllerCommandingComponent lives on DefaultPlayerController.et (so every mode using the default controller chain has it) [SRC]. Builds the radial menu from SCR_PlayerCommandingMenuConfig (action/config pairs `Configs/Commanding/CommandingMenuActionConfigPairs.conf`, map menu `CommandingMapMenu.conf`); entries gated by `CanBeShown/CanRoleShow/CanBePerformed/CanBeExecuted`. `CanRoleShow` for group commands = `SCR_PlayerControllerGroupComponent.IsPlayerLeaderOwnGroup()` (uses faction + GetPlayerGroup + leader id, not group ID).
- Cursor position [SRC]: `PrepareExecuteCommand` -> `PhysicsCommandTrace()` (TraceSegmented from camera pos along camera forward, 10 km, ENTS|WORLD, excluding own entity and vehicle) -> OnTraceFinished -> `ExecuteCommand(targetPosition)`. From the map: `OnMapCommandPerformed` uses worldPos + GetSurfaceY + 0.5 m. Target-self commands (follow, halt, combat mode) use the character origin.
- Client `ExecuteCommand` [SRC]: `playersGroup = groupManager.FindGroup(groupController.GetGroupID()); if (!playersGroup) return;` (SILENT return) -> get/create slave (retry every 100 ms) -> `command.VisualizeCommand(pos)` (pointer HUD: SCR_PlacedCommandInfoDisplay from `PlacedCommandInfoDisplay.conf`, only if the command has `m_bShowPreview`) -> `Rpc(RPC_RequestExecuteCommand, idx, cursorTarget, slaveGroupRplId, pos)`.
- Server `SCR_CommandingManagerComponent.RequestCommandExecution` [SRC]: if command `ShouldPlayAIResponse()` (default true): `GetPlayerGroup(playerID).GetSlave()` must be non-null or it RETURNS without broadcasting (no waypoint, no voice). Responder = slave `GetLeaderAgent()` entity. Then `RPC_DoExecuteCommand` broadcast to all.
- Waypoint [SRC]: `SCR_WaypointGroupCommand.Execute` (server branch) clears the slave's waypoints, spawns local wp prefab (move: `Prefabs/AI/Waypoints/AIWaypoint_Move.et`) at the position, completion radius 5, `slave.AddWaypoint(wp)`; `m_bForceCommand` sets priority PLAYER. Command list in `Configs/Commanding/Commands.conf`: `waypointMove`, `waypointMoveForced`, `follow`, `halt`, `waypointDefend`, `waypointSearchAndDestroy`, `waypointSuppress`, `recruitAI`, `removeAI`, combat-mode commands, artillery, emotes.
- Voice [SRC]: after `Execute` returns true, `PlayCommanderSound`: needs the commander's SCR_ChimeraCharacter (player controlled entity) with SignalsManagerComponent + SCR_CommunicationSoundComponent; sets signals SoldierCalled=1000, SoldierCaller=0, Seed; `SoundEventPriority(command.m_sSoundEventName, 50)` (move SOUND_CP_MOVE_CLOSE, follow SOUND_CP_FOLLOW_LEADER, halt SOUND_CP_STOP). 2 s later the slave leader plays SOUND_CP_POSITIVEFEEDBACK (same two components needed; an empty slave group = no reply). Gesture is played via `CommandExecutedCallback` RPC to the commander.
- Server also: `GetOnPlayerSpawned -> ResetSlaveGroupWaypoints` (clears slave waypoints for the leader on respawn).

## 2. Custom game mode preconditions and the group-ID -1 observation
Conflict (`Prefabs/MP/Modes/Conflict/GameMode_Campaign.et`) vs `GameMode_Base.et` [SRC]:
- GameMode_Base already has: SCR_GroupsManagerComponent (`m_sDefaultGroupPrefab` Prefabs/Groups/PlayableGroup.et), SCR_MapMarkerManagerComponent, SCR_MapConfigComponent, SCR_RadialMenuItemsComponent, SCR_TaskManagerUIComponent, SCR_TextsTaskManagerComponent, SCR_TaskFinishHistoryManagerComponent, SCR_CallsignManagerComponent.
- Conflict adds: SCR_CommandingManagerComponent (m_iMaxAIPerGroup 4), SCR_GroupTaskManagerComponent, SCR_TaskCreatorComponent, SCR_TaskNotificationManagerComponent, SCR_TaskSolverManagerComponent, its own PlayableGroup prefab (Campaign_PlayableGroup.et), PlayerControllerPrefab DefaultPlayerControllerMP_Campaign.et.
- Player controller (DefaultPlayerController.et chain) already carries SCR_PlayerControllerCommandingComponent, SCR_PlayerControllerGroupComponent, SCR_RadialMenuGameModeComponent, SCR_TaskSystemNetworkComponent, SCR_TaskListDisplay (HUD). Nothing extra needed unless the mode sets a custom PlayerControllerPrefab.
- Also needed: player has a Faction (GetPlayerGroup uses GetPlayerFaction), group faction set + group registered in GroupsManager under that faction, player is leader, character has SCR_CommunicationSoundComponent + SignalsManager (default characters do).

ROOT CAUSE of "works at ID -1, stops after AssignGroupID" [SRC]:
- `SCR_PlayerControllerGroupComponent.m_iGroupID` defaults to -1 and is ONLY set by `RPC_AskJoinGroup` (which also replicates it via `RPC_DoChangeGroupID`), cleared by Reset/Remove. `SCR_GroupsManagerComponent.AddPlayerToGroup(groupID, playerID)` only calls `group.AddPlayer`; it does NOT update the player controller's m_iGroupID.
- Client `ExecuteCommand` calls `FindGroup(groupController.GetGroupID())` = `FindGroup(-1)`. `FindGroup` is a plain loop `groups[j].GetGroupID() == groupID`, so with a squad whose ID is still -1 it matches by accident. After `AssignGroupID` the squad has ID N, `FindGroup(-1)` is null, `ExecuteCommand` returns silently BEFORE `VisualizeCommand` and the RPC: no pointer marker, no server execution, no commander voice. Menu entries still show because the gating uses GetPlayerGroup (faction + IsPlayerInGroup), not the ID.
- Unexplained: "commands still move the squad" after assignment cannot come from this path (no RPC is sent). Probably our own code moves it or old waypoints persisted; check.
- FIX: assign group ID first (AssignGroupID / CreateNewPlayableGroup), then join the controller through the vanilla path: `SCR_PlayerControllerGroupComponent.GetPlayerControllerComponent(pid).RequestJoinGroup(group.GetGroupID())` (vanilla `RejoinPlayer` calls it from the server; `RPC_AskJoinGroup` adds the player and sets+replicates m_iGroupID). Requires group faction == player faction and group not full. Do not also call AddPlayerToGroup for the same player.
- Slave group: the AI that should obey must be in the SLAVE group (`AddAgent` into it), the players in the master. Create the slave like CreateNewPlayableGroup does: spawn `commandingManager.GetGroupPrefab()`, `DeactivateAI()`, `groupsManager.RequestSetGroupSlave(masterRplId, slaveRplId)`; or let the leader's first command trigger `RequestCreateSlaveGroup`. If the scene squad is registered as master and holds the AI, commands go to an empty slave.

## 3. SCR_Task for a player without a group ID
- Server only: all mutators error on clients (`Replication.IsClient()`) [SRC SCR_TaskSystem.c]. SCR_TaskSystem is a GameSystem, auto-registered [WIKI].
- `SCR_Task t = SCR_TaskSystem.GetInstance().CreateTask(ResourceName prefab, string uniqueTaskID, string name, string desc, vector pos, int playerId = -1)`. Empty prefab -> `Prefabs/Tasks/BaseTask.et` ({1D0F815858EE24AD}); ExtendedTask.et = {CF6A2A13DF7B1018}. Duplicate ID returns null. Prefab needs RplComponent (they have it). Pass playerId -1 for scripted tasks (>-1 marks author and counts to a per-player limit of 3).
- DEFAULTS [SRC SCR_Task.c attributes]: ownership EVERYONE, visibility EVERYONE, UI visibility ALL, state CREATED. With defaults the task is visible in the J task list and on the map and assignable by anyone; NO group ID needed. Group ID only matters for ownership/visibility GROUP (`executor.GetGroupID() <= -1` = not visible/assignable) and group executors.
- Restrict to one player: `SetTaskOwnership(t, SCR_ETaskOwnership.EXECUTOR)`, `SetTaskVisibility(t, SCR_ETaskVisibility.EXECUTOR)`, `AddTaskExecutor(t, SCR_TaskExecutor.FromPlayerID(pid))`. Enums: Ownership NONE/EXECUTOR/GROUP/FACTION/EVERYONE; Visibility NONE/EXECUTOR/ASSIGNEES/GROUP/FACTION/EVERYONE; UIVisibility NONE/MAP_ONLY/LIST_ONLY/ALL.
- Assign: `SCR_TaskSystem.GetInstance().AssignTask(t, SCR_TaskExecutor.FromPlayerID(pid), true)` (force replaces the player's current task; one assigned task per executor). `CanTaskBeAssignedTo` must pass (state not COMPLETED/FAILED/CANCELLED, ownership match). First assignee flips state to ASSIGNED. UI Assign button goes via SCR_TaskSystemNetworkComponent -> same server AssignTask.
- UI needs [SRC]: SCR_TaskManagerUIComponent on the game mode (in GameMode_Base), HUD SCR_TaskListDisplay (in DefaultPlayerController), player has an SCR_Faction (current-task hint `ToggleCurrentTask` returns without faction or playerID<=0). Map task list comes from the map config (task tabs config `Configs/Task/TasksTabConfig_Base.conf`, Conflict uses `_Conflict`).
- Prefabs [SRC]: `Prefabs/Tasks/MoveTask.et` (SCR_TriggerTask, 50 m sphere faction trigger via BaseTriggerTask.et), NeutralizeTask.et (SCR_MoveTask), DefendTask.et, SeizeTask.et, CustomTask.et; ScenarioFramework tasks in `Prefabs/Systems/ScenarioFramework/Tasks/` [WIKI]. For a plain scripted attack/recon/move task use BaseTask/ExtendedTask and complete it from our own logic.
- Complete/update: `SetTaskState(t, SCR_ETaskState.COMPLETED|FAILED|CANCELLED)` (replicated; removes assignees; shows in the completed tab). States CREATED/ASSIGNED/PROGRESSED/COMPLETED/FAILED/CANCELLED. Extended tasks: `AddTaskProgress` (0-100, 100 -> COMPLETED). `MoveTask(t, pos)`, `DeleteTask(t)`, `SCR_TaskSystem.GetTaskFromTaskID(id, false)`, listener `SCR_Task.GetOnTaskStateChanged()`. SCR_MoveTask auto-completes when an assignee is within m_fMaxDistance (5 m) if completion type AUTOMATIC; otherwise do your own distance/trigger check.
