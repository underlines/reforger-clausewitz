# Radial menu and a new input action (WP2, 2026-10-14)

Sources: vanilla scripts read with the enfusion MCP / PakVirtualFS (game 1.8), wiki `Arma_Reforger:Input_Manager`, `Data_Modding_Basics`, and the installed Workshop mod WCS_VON (a published mod that adds a keybind). Nothing was run in the game.

## Vanilla radial menu
- `SCR_RadialMenu : SCR_SelectionMenu` is the menu; ONE global instance lives on the player controller (`SCR_RadialMenuGameModeComponent`, `SCR_RadialMenu.GlobalRadialMenu()`), updated by `RadialMenuSystem`. The commanding menu (`SCR_PlayerControllerCommandingComponent`) and emotes use it; the map and the editor have their own.
- `SCR_RadialMenuController` (script class, normally config-loaded) holds `m_RMControls` (`SCR_RadialMenuControllerInputs`: `m_sOpenAction`, `m_bCloseOnReleaseOpen`, `m_bPerformOnClose`, `m_bCloseOnPerform`, `m_bShowWhileUnconcious`, `m_bUseQuickActions` 1-9, ...). Its constructor listens to `m_sOpenAction` (DOWN) -> `OnInputOpen()` -> `Control()` (global menu `SetController(owner, m_RMControls)`) -> `SetMenuDisplay()` -> `Open()`.
- Taking control with other inputs makes the previous controller clear the menu, close it and drop its listeners (`OnMenuControllerChanged`). So several consumers share the global menu safely IF each calls `Control()` before it adds entries. We do (CLW_HqRadialController.OnInputOpen).
- Levels: `SCR_SelectionMenuCategoryEntry` (children in `m_aEntries`); `PerformEntry` calls `entry.Perform()` (-> `OnPerform()`) BEFORE `OpenCategoryEntry` reads `GetEntries()`, so a category subclass can build its children lazily in `OnPerform` (CLW_HqRadialCategory). Back (`RadialBack`) leaves a level; at the top it closes.
- Look of an entry: the default layout shows only an icon; the name shows in the middle of the circle for the pointed entry. `SCR_SelectionMenuEntryCommand` (layout `{A87A2A3CA0018423}UI/layouts/Common/RadialMenu/SelectionMenuEntryCommand.layout`) adds a small text under the icon (`SetCommandText`). Icons: image set `{A4A692135635424E}UI/Imagesets/Commanding/Commanding_Icons.imageset` (custom, defend, fire-at-will, follow, get-in/out, halt, heal, hud-arrow, hud-circle, look-at, mount-passenger, patrol, recruit, search-destroy, supress, ...).
- Decision: the GLOBAL menu with our own controller subclass created in script (`m_RMControls` assigned in the constructor; attribute defaults do not apply to `new`, so every field and `m_sEnableControl` are set by hand). No controller `.conf` needed.

## New input action
- VERIFIED pattern (WCS_VON, a working Workshop mod): `Configs/System/chimeraInputCommon.conf` in the addon is a DELTA file (only the added nodes; same path and same resource GUID as the vanilla file `{795184CF9AD764DB}`, "Override" in Workbench; wiki Data_Modding_Basics: configs "can be modified", the changes are merged onto the original). It adds `ActionManager > Contexts > ActionContext <existing context> > Actions > Action <Name> { InputSource InputSourceSum ... }`. `keyBindingMenu.conf` (`{4EE7794C9A3F11EF}`) is overridden the same way to list the action in Options > Keybinds (own category). GUIDs from `_tools/guid-lookup.ps1`.
- Context: `VONContext` (priority 110) is activated every frame by `SCR_VONController.Update` while the player is not unconscious/disabled, in the character and in vehicles; WCS_VON uses it for F3. The vanilla `OpenCommandMenu` lives in `CommandingContext`, whose activation is not visible in scripts. We use `VONContext`.
- Key: `U`. Vanilla uses `KC_U` only for `GroupAcceptInvite`, which is in the group menu contexts (`GroupMenuContext`, player menu), not in gameplay. H and J are used by this mod, Y = Game Master. `FilterPreset "hold"` like `OpenCommandMenu` (DOWN fires on hold, UP on release -> hold-to-open, release performs the pointed entry).
- Not verified in the game: that the delta file merges as expected for a NEW .conf in our addon (the lead rebuilds the resource DB), that `VONContext` stays active with the radial open (it should: the radial adds `RadialMenuContext`), gamepad (no binding added).
- Fallback: chat command `/hqr` opens the circle without a held key (click to confirm, back to close).
